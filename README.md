 # Django REST Framework 

Проект представляет собой защищенную backend-часть для платформы онлайн-обучения. Реализовано глобальное разграничение прав доступа для модераторов и владельцев объектов, а также внедрена **JWT-авторизация**.

## 🛠 Добавленные технологии
* `djangorestframework-simplejwt` (авторизация по токенам)
* `django-filter` (фильтрация платежей)
* `coverage` (измерение тестового покрытия кода)
* `drf-yasg` (генерация Swagger и ReDoc)
* `stripe` (официальный SDK платежной системы)
* `celery` (управление очередями задач)
* `redis` (брокер сообщений и бэкенд результатов)
* `django-celery-beat` (планировщик периодических задач в БД)

## 🚀 Реализованная бизнес-логика

### 1. Асинхронная рассылка уведомлений (Задание 2)
* Реализована Celery-задача `send_course_update_email` в приложении `materials`. При обновлении курса или любого его урока всем подписчикам курса асинхронно отправляется email-уведомление.
* **Защита от спама:** Внедрена проверка времени последнего изменения. Оповещение отправляется только в том случае, если курс не обновлялся в течение последних **4 часов** (`timezone.now() - course.last_update > timedelta(hours=4)`).

### 2. Периодическая блокировка пользователей (Задание 3)
* Реализована фоновая задача `check_inactive_users` в приложении `users`. Она проверяет дату последнего входа пользователей по полю `last_login`.
* Если пользователь не заходил на платформу более **1 месяца (30 дней)**, его аккаунт автоматически деактивируется (флаг `is_active=False`).
* **Оптимизация:** Обновление статусов в базе данных происходит оптимизированным батчем (`bulk update` через метод `.update()`), а не по одному объекту в цикле.
* Задача добавлена в расписание `CELERY_BEAT_SCHEDULE` в настройках проекта с интервалом запуска раз в сутки.

## ⚙️ Инструкция по запуску асинхронного режима

1. **Запустите брокер очередей Redis** на локальном хосте. После установки `.msi` пакета служба автоматически работает в фоновом режиме на стандартном порту `6379`.
2. **Запустите Celery-воркер** в отдельном терминале для обработки задач:
   ```bash
   # Для Windows (используется пул solo):
   celery -A config worker --loglevel=info -P solo
   
   # Для macOS / Linux:
   celery -A config worker --loglevel=info
   ```
3. **Запустите планировщик Celery Beat** в третьем терминале для генерации периодических задач:
   ```bash
   celery -A config beat --loglevel=info
   ```
4. **Запустите стандартный веб-сервер Django**:
   ```bash
   python manage.py runserver
   ```

## 🚀 Новые возможности проекта

### 1. Документирование API (Задание 1)
Реализована автоматическая генерация спецификации OpenAPI. Документация доступна в интерактивном и статическом форматах по следующим адресам (доступ открыт для всех пользователей):
* `GET /swagger/` — Интерактивный интерфейс **Swagger UI** с возможностью тестирования эндпоинтов (Try it out) прямо из браузера.
* `GET /redoc/` — Чистый структурированный интерфейс **ReDoc**.

### 2. Интеграция со Stripe (Задание 2 + Дополнительное задание)
Реализован изолированный сервисный слой (`users/services.py`) для работы с API Stripe в безопасном тестовом режиме (`Sandbox`).
* **Эндпоинт создания платежа:** `POST /users/payments/create/`. Принимает ID оплачиваемого курса или урока и сумму.
* **Логика работы бэкенда:** 
  1. На сервере автоматически регистрируется продукт в системе Stripe.
  2. Генерируется цена. Сумма оплаты конвертируется в минимальные денежные единицы (копейки/центы) в соответствии с требованиями Stripe (`unit_amount`).
  3. Создается сессия оплаты Checkout. Полученные `session_id` и прямая ссылка `payment_link` сохраняются в базу данных, а поле `user` автоматически привязывается к текущему авторизованному пользователю.
  4. Клиент получает статус `201 Created` и готовую ссылку на проведение платежа.
* **Проверка статуса:** `GET /users/payments/status/<session_id>/` — Позволяет по идентификатору сессии запросить у Stripe актуальный статус проведения транзакции.

### 1. Валидация ссылок (Задание 1)
Для сохранения уроков реализована строгая проверка поля `video_url` в `LessonSerializer`. Допускаются ссылки, ведущие исключительно на видеохостинг **youtube.com** (или короткий домен **youtu.be**). При попытке привязать сторонний ресурс API выдает понятную ошибку валидации со статусом `400 Bad Request`.

### 2. Модель подписки на обновления курсов (Задание 2)
* Создана модель `Subscription` со связями с пользователем и курсом. На уровне базы гарантирована уникальность пары «пользователь-курс» (`unique_together`).
* Реализован эндпоинт-переключатель `POST /materials/courses/subscribe/`. Если подписка у текущего пользователя на курс уже есть — она удаляется, если нет — создается.
* В `CourseSerializer` добавлено динамическое поле `is_subscribed`, отображающее статус подписки текущего авторизованного пользователя на этот курс.

### 3. Пагинация данных (Задание 3)
Реализован кастомный пагинатор `MaterialPagination` на базе `PageNumberPagination` со следующими параметрами:
* Размер страницы по умолчанию: 5 элементов.
* Возможность изменения размера клиентом через параметр: `?page_size=`.
* Максимальный лимит страницы: 50 элементов.
Пагинатор успешно подключен к выводу всех курсов и уроков.

### 🔑 Работа с JWT-токенами
Для отправки запросов к защищенным эндпоинтам через Postman выполните следующие шаги:
1. Отправьте `POST`-запрос на `/api/token/`, передав в теле (`Body`) ваш `email` и `password`.
2. Скопируйте полученный `access`-токен.
3. Вставляйте его во все последующие запросы в заголовок: `Authorization: Bearer <ваш_токен>`.

## 🗺 Карта эндпоинтов (Маршрутизация)

В проекте работает **Главная страница-навигатор** (`http://127.0.0`), откуда можно переходить к тестированию.

### 🔐 Авторизация и Управление пользователями
* `POST /users/register/` — Регистрация нового пользователя (**доступна анонимам**).
* `POST /api/token/` — Получение пары access/refresh JWT-токенов (**доступно анонимам**).
* `POST /api/token/refresh/` — Обновление access-токена.
* `GET /users/` — Список всех пользователей (выводятся строго публичные данные).
* `GET/PUT/PATCH/DELETE /users/profile/<id>/` — Управление профилем.
  * **Дополнительное задание:** Если авторизованный пользователь запрашивает *свой* профиль, отдается полная информация с историей платежей. Если запрашивается *чужой* профиль — отдается укороченный публичный JSON (без пароля, фамилии и платежей).

### 📚 Курсы и Уроки (Права доступа)
* `GET /materials/courses/` и `GET /materials/lessons/` — Просмотр контента.
* `POST /materials/courses/` и `POST /materials/lessons/create/` — Создание сущностей. При создании поле `owner` автоматически заполняется текущим пользователем.
* Управление конкретными объектами (`retrieve`, `update`, `destroy`).

**Матрица прав доступа (Permissions):**
* **Обычный пользователь:** Может создавать контент. Имеет полный доступ (редактирование/удаление) **только к своим** курсам и урокам.
* **Модератор (группа "модераторы"):** Может просматривать и редактировать **любые** курсы и уроки в системе для контроля качества, но **не имеет права создавать новые или удалять существующие** объекты.

## 🐳 Запуск проекта через Docker Compose

Проект полностью оркестрован с помощью Docker Compose. В едином окружении разворачиваются веб-сервер Django, база данных PostgreSQL, брокер Redis, а также фоновый воркер и планировщик Celery.

### Настройка окружения

Убедитесь, что для работы внутри Docker указаны следующие хосты:
   ```env
   DATABASE_HOST=db
   CELERY_BROKER_URL=redis://redis:6379/0
   CELERY_RESULT_BACKEND=redis://redis:6379/0
   ```

### Команды для управления контейнерами

* **Сборка образов (без кэша) и запуск всех сервисов:**
  ```bash
  docker compose build --no-cache && docker compose up
  ```
  *(Для PowerShell используйте разделитель `;` вместо `&&`)*

* **Обычный запуск проекта (после первой сборки):**
  ```bash
  docker compose up
  ```

* **Остановка всех контейнеров и удаление сетевых ресурсов:**
  ```bash
  docker compose down
  ```

### Доступ к приложению
После успешного запуска всех сервисов локальный сервер и документация API доступны по адресам:
* Главная страница / Панель навигации: [http://localhost:8000/](http://localhost:8000/)
* Документация Redoc: [http://localhost:8000/docs/](http://localhost:8000/docs/)
